# 业务知识库

本技能是总入口。进入新业务建库、收到一批资料、被问知识库怎么用，或不确定下一步时，先加载它，再按任务加载配套：

- 学习、登记、深读、抽数和拟改：[业务知识库-学习入库](sand-workflow:skill-1794580809881)
- 按某一种用法取材料、加工或出门把关：[业务知识库-用法检索](sand-workflow:skill-1794580824884)
- 增量扫描、关系校验、复审或体检：[业务知识库-定期校验](sand-workflow:skill-1794580838391)

本套技能只保留可复用的方法。业务里的事实、价格、口径和客户信息，只存在该业务自己的知识库里。一个业务一个库，互不混写。不要把某个业务的内部数字或未公开口径写进本技能。

## 硬性规则

- 不编造。没有出处的数字、承诺和「已上线」判断，不得写成现行事实或对外口径。
- 冲突先挂起，并排保留，不合并、不换算、不取中间值。
- 培训稿不等于已上线；设计稿不等于可售卖能力；竞品库不等于对客话术；案例素材不等于证据；价格结构不等于可以报出的死价；内部系统不等于对外产品卖点。
- 学习可以批量进行；写入现行页（能力状态、对外口径、关键数据）必须先得到使用者确认。
- 权威原文不挪走、不改写。回写权威稿必须单独授权；失败了据实说明，不换一条路径乱写。
- 不用外网搜索去补业务死数（价格、效果、保障、对外可比规模等）。缺口挂待确认，由使用者拍板。
- 交给助手的资料默认全部深读。读不了的如实标明，不假装已读。

## 四层结构

| 层 | 回答的问题 | 要点 |
|---|---|---|
| 原料层 | 原文在哪、是谁在什么时间主张的 | 原文不改、不删、不合并。先记指针；只在需要识别、渲染、转写，权威位置不稳定，或使用者明确交来处理时，才留只读工作拷贝。 |
| 事实层 | 这个业务现在是什么 | 能力必须标明状态：已上线、部分上线、设计中、证据不足。规划不能写成现状。 |
| 口径层 | 能讲什么、不能讲什么 | 现行可讲、待确认、禁止对外（可加仅对内）。对外主张进入主张登记册。 |
| 用法层 | 这一次要完成哪类作业 | 按八种用法设入口。用法页只引用事实和口径，自己不另造数字。 |

页面按职责拆开：图景页只解释现状，能力清单只陈述事实和状态，用法入口只规定怎么取材料和怎么产出，培训页只教打法。发现混了就拆页。

## 八种用法

1. 建立正确图景
2. 面向一个具体对象做封装
3. 面向内部角色做赋能
4. 对照现状做建设和改进
5. 应对比较和质疑
6. 出门前把关
7. 对内复盘和取舍
8. 当场查一个具体问题

大多数业务第一轮先建第 2、3、4、6 种用法的入口。其余先做轻量入口和检索路径。目录按用法进入，不按文件类型进入。

## 核心文件与关系

契约和导航：`知识库契约`、`用法目录`、`来源与学习台账`、`变更日志`。

事实层：`业务图景`、`能力与边界`、`客户与市场`、`成交与履约`、`内部系统`、`经营节奏`。新业务可先出图景和能力清单，其余预留位置再补。

口径层：`口径三态`（便于检索现行与禁止）、`开放问题台账`、`主张登记册`（每条对外主张有编号、状态、证据、拍板人、生效日、复审期、下游依赖）。

用法层：八个用法入口。答题卡结构为：触发、可讲答案、先问什么、禁止声称、下一步、证据。

另加 `关系图谱`：既画业务主线与分界，也让每条现行口径能点回原文。图谱不替代正文。

关系是单向取证、反向可追溯：用法目录 → 用法入口 → 事实页或口径页 → 来源摘要 → 原文。任何一句现行口径或能力状态，都要能回到来源。能力与边界是事实层枢纽；口径与主张登记册是对客输出的门；开放问题只进待确认，不直接对外使用。

## 原文存放

原文默认仍留在原来的权威位置。原料层先记指针：路径或链接、文档 ID、标题、日期、版本。

工作拷贝只用于读取，不代替原文，也不回写。云文档以线上那一份为原文；学习时抓取当时正文作为工作拷贝，页面更新后再取新版对照，不用过期副本冒充最新稿。

## 使用者节点

初始化时，使用者说明：这是什么业务、权威资料在哪、口径由谁拍板、眼下主要用哪几种用法，然后交来文件或云文档。

之后只需：确认拟改清单后再写入现行页；出成稿前说明要出什么、给谁用、边界在哪；拍板待确认项；回写权威稿时单独授权。

助手不每页打断。只有正文取不到或没权限、图上关键数字看不清又会影响口径、缺少输出形态，或需要授权时，才中断询问。

## 流水线

1. 定边界（新业务）或接收本批资料。初始化时除业务、权威源、拍板人、主要用法外，还要确认固定资料空间和检查时间。
2. 加载「学习入库」：登记 → 全量深读 → 抽出结构化主张 → 交出材料包和拟改清单。
3. 使用者确认后，写入现行页；未确认的停在来源页和待确认。
4. 按用法作业时，加载「用法检索」。
5. 初始化结束前，必须同时落实定期检查：把入库后短检、承诺变更立即复审、拍板回收写入契约；为固定空间增量扫描和每周关系与口径校验创建到点例行（体检可并入周检）。若已有同类例行，对齐补缺，不另起打架的台账。没有把到点检查立起来，就不能算初始化完成。之后按这些例行加载「定期校验」。
6. 写错了：回退被误改的现行页，记入变更日志，不改原文，不偷偷覆盖历史版本。

## 第一轮最小闭环

文件：契约、用法目录、来源与学习台账、变更日志、业务图景、能力与边界、口径三态、开放问题台账、主张登记册、四个主用法入口（其余四个先做轻量入口）、关系图谱。

机制：学习入库与拟改确认门禁、编译层优先的检索、使用者输出输入、原文指针与回写授权、回退规则，以及上一节的定期检查规则和到点例行。

未拍板的内容继续挂在待确认，不写进现行可讲。结构与机制一次立好，内容随作业反补，不求一次穷尽。
