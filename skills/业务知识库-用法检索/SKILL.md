# 业务知识库-用法检索

在 [业务知识库](sand-workflow:skill-1794580790441) 之后加载。适用于按某一种用法取材料、加工和输出。

## 检索通则

检索可以通用，加工和输出不能自动完成。

先走编译层：用法目录 → 对应用法入口 → 事实页和口径页（含主张登记册）→ 来源摘要 → 必要时回原文。编译页适合稳定、要可追溯、会反复问的问题。

尚未编译的新材料（新会议、未读媒体、刚抓到的网页或竞品信息）可以查原文或外搜，但必须标明「未经编译」，不得冒充已经整理过的结论，也不得自动升成现行口径或对外主张。

每条被引用的现行口径，都要能沿着「主张 → 证据」回到原文。关系图谱要保留这类边，不只画业务主线。

禁止用外网搜索去补官方业务死数，例如价格、效果保障、库规模等对外可比数字。这类缺口挂待确认，由使用者拍板。

## 先要使用者输入再输出

取到材料之后、写成可交付成稿之前，必须先有使用者输入：要出什么、给谁用、有什么限制。缺这一步时先交材料包，并问清输出形态，不擅自写成对客稿、培训稿或需求方案。

## 材料包格式

一次用法检索的材料包固定包含：

- 用法类型与本次任务
- 先读过的编译页
- 采用的主张与能力状态（带来源）
- 冲突或待确认项（并排列出，不自行取舍）
- 未经编译的补充材料（如有，单独标注）
- 还缺什么
- 建议的输出形态（等使用者确认）

## 八种用法的策略

1. **建立正确图景**  
   只根据图景页、能力清单和已确认事实，交代现状主线与分界。机会不足时如实说。不把规划、培训愿望或外部传闻补成「现在就是这样」。

2. **面向一个具体对象做封装**  
   先锁定对象（客户、行业或场景），再从已上线和部分上线的能力中挑选组合，过口径门。材料包说明用了哪些能力、哪些做不到、哪些待确认。方案形态、承诺边界等必须等使用者输入。不把设计中的能力写成可售卖模块，不把案例素材写成该对象已经验证的效果。

3. **面向内部角色做赋能**  
   按角色取「可讲 / 先问 / 禁止声称」。只使用现行可讲主张和已确认事实。培训稿、历史分享可作素材，但不是已审对客话术。出门材料另走把关，不在赋能稿里偷偷加码。

4. **对照现状做建设和改进**  
   先读能力与边界，分清已上线、部分上线、设计中、证据不足。需求和建议只能写在「对照现状」的基础上，并标出将改的是产品、流程还是口径。不得把建设方案写回现状页，好像已经上线。

5. **应对比较和质疑**  
   走双通道：我方稳定事实和口径走编译层；竞品情况与策略可以外搜或查新材料，但新信息先当证据，标明「未经编译」，不自动写成现行口径，也不自动变成对客话术。比较时只陈述有出处的差异，不夸大我方、不把对方宣传当已核实事实。涉及我方价格、保障、规模等死数，仍只引用已确认主张。

6. **出门前把关**  
   按出门清单核对即将带出的每一句：是否在现行可讲中、证据是否仍有效、是否误用待确认或禁止项、是否把设计写成已上线、是否承诺了效果或未授权的价格。通不过就改稿或挂起，不靠现场发挥补一句。

7. **对内复盘和取舍**  
   可用更完整的内部事实、冲突台账和经营材料。结论要分开写：已核实事实、待确认判断、建议的取舍。复盘意见不自动变成对外口径；若要改现行主张，走拟改清单和确认门禁。

8. **当场查一个具体问题**  
   先查编译页和主张登记册，给短答案、出处和状态（现行 / 待确认 / 禁止 / 证据不足）。编译层没有、又属于挥发材料时，可查原文或外搜，但必须标明未经编译。查不到就说查不到，不编。

## 答题卡

对客或对内可复用的回答，按下面结构写进用法入口，不另造数字：

- 触发（什么情况下用）
- 可讲答案
- 先问什么
- 禁止声称
- 下一步
- 证据（主张编号或来源）

## 出门清单

- 每句对外的话都能在主张登记册里找到现行记录，或被明确标为不可用
- 没有使用待确认、禁止对外、未经编译的材料冒充结论
- 没有把设计、培训或案例升成已上线或已验证效果
- 价格、保障、规模等死数未经确认不得报出
- 使用者要求的输出形态、对象和限制已被遵守
