# 业务知识库-定期校验

在 [业务知识库](sand-workflow:skill-1794580790441) 之后加载。用来避免知识库看起来齐全，其实已经过时或讲错。

## 校验分四层

1. **入库后短检**  
   每次新资料走完学习流水线，当天更新台账、日志和被改到的核心页，核对拟改项是否只在确认后写入，并检查本批有没有把设计或培训写成已上线。

2. **固定空间的增量扫描**  
   若该业务有固定资料空间（例如例会记录、产品文档区、共享知识库），按约定周期扫描。有新材料就进入学习入库；没有就在变更日志里记「无增量」，不拿旧材料冒充本期已更新。扫描不等于深读完成，新材料仍要按学习入库处理。

3. **每周关系与口径校验**  
   专门查五件事：新材料和现行口径有没有打架；有没有把设计或培训稿写成已上线；能力清单的状态和来源是否还一致；用法入口指向的页还在不在；来源已经更新、但编译页还停在旧日期。结果写入当周周报，并刷新常驻体检看板，不再另发一份「有变化才出」的简报。

4. **按易变程度复审，外加定期体检**  
   价盘和对外承诺随变更立即复审，并核对这些主张的下游依赖（方案、培训、答题卡）。竞品有新动作或按更长周期看，新信息先当未经编译的证据。案例在对象情况变化时更新，且案例素材不得自动变成证据。  
   定期体检：断链、孤儿页、同一事实两页说法不一致、双台账、以及「未读却标成已读」。

## 拍板回收

使用者完成拍板后，必须回收一次：待确认改为现行或禁止，同步改主张登记册和相关核心页，记入变更日志。需要回写权威稿时单独询问，没有授权不动。回写失败就停止并说明，不换途径重试乱写。

## 体检与汇报

检查结果要让使用者随时能看清现状，不能只在有变化时才发一条短讯。

1. **常驻体检看板**：一张当前状态页，每次例行都刷新。打开即可看，不必等周报。
2. **每周一份固定六块周报**，无论有没有变化都写、都发；没有变化的块一行带过。六块固定顺序：
   1. **总体状态**：一句话健康判断 ＋ 各用法就绪度（A 可直接用 / B 材料够、缺入口或门 / C 材料散、缺核心页）。
   2. **本周知识进账**：新学了哪些、哪些已编进核心页、学了还没编译的积压。
   3. **更新与变化**：事实页或口径改动，主张登记册状态变化。
   4. **异常**：例行失败与补跑、断链、未读标已读、两页说法不一、敏感拦截、同步冲突。
   5. **你的待办**：需拍板事项按急缓排序，每条写为什么需要使用者、不拍会卡住什么；对使用者批注逐条回复。
   6. **业务洞察**：趋势、矛盾、机会；每条标来源，事实与推断分开。洞察不等于现行口径，不自动进入主张登记册。没有能由编译页支撑的洞察，就写本周无新增，不要凑条。
3. **增量扫描类例行**只在有实质内容时发短讯，该周汇总统一进入这份周报。

## 回退

发现现行页写错：回退被误改的页面到确认前状态，保留原文不动，在日志中写下错误与回退。不靠再写一版新正文悄悄覆盖，也不把未确认内容重新写进现行页。

## 初始化时必须同时建立

初始化一个新业务知识库时，定期检查不是建完文件后再补的可选步骤。结束前必须同时落实：

- 事件触发的规则写入该业务契约：入库后短检、价格或对外承诺变更后的立即复审、拍板后回收。
- 到点执行的例行：问清固定资料空间和检查时间，创建「固定空间增量扫描」和「每周关系与口径校验」（定期体检可并入周检），并立好常驻体检看板与每周六块周报的位置和格式。若已有同类例行，对齐并补缺，不要另起一套互相打架的台账。
- 没有把到点检查例行和汇报机制立起来，就不能算初始化完成。

## 与例行的衔接

本技能描述的是检查方法。初始化创建的例行，或该业务已有的同类例行，都按那些时间执行本技能。方法通用，台账和页面属于该业务自己的库。
